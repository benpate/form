# form — Notes for AI Agents

This package renders HTML forms from a rosetta data schema plus a tree of `Element` UI definitions, and applies posted `url.Values` back onto the object. [README.md](README.md) covers usage; [doc.go](doc.go) documents the API surface; [widget/README.md](widget/README.md) covers the built-in widgets and the registry contract in depth.

## Rendering and the widget registry

- **An unregistered `Element.Type` fails the WHOLE render with an error, not a blank widget.** `Element.Widget()` in [element.go](element.go) returns `derp.Internal("form.Widget", "Unrecognized form widget", ...)` from a plain package-level map in [registry.go](registry.go). Nothing registers widgets implicitly — every `main()` and every test binary that renders a form must call `widget.UseAll()` (or `form.Use`) first, usually in `TestMain`. Callers that ignore the error (e.g. `fmt.Println` in an Example) see an empty page; any `ExampleXxx` that renders a form needs an `// Output:` comment so CI catches this.
- **There is no `"number"` widget.** The `"text"` widget reads the input type from the DATA schema, so a `schema.Integer` path renders `<input type="number" step="1">` with min/max from the schema. The full registered set is the `UseAll()` body in [widget/widget.go](widget/widget.go) — treat that function as the source of truth for type names.
- **The registry is init-time only and has no mutex on purpose.** Populate it during startup, before any goroutine renders a form. Do not "fix" it with a lock; this is the standard registration pattern.
- **Errors surface only as a wrapped derp chain.** `Error()` prints just the outermost `location: message`; when debugging a blank render, unwrap with `errors.Unwrap` in a loop (or derp's report helpers) to find the failing element.

## Escaping: values are untrusted, definitions are trusted

- **Never pass a data value to `html.Builder.WriteString`.** That is the embedded `strings.Builder` method: it does not escape, AND it skips the builder's pending end bracket, so the text lands inside the open tag. Both failure modes are invisible in casual testing. Use `.InnerText()` for any end-user data, or the `drawValue` helper in [widget/utils.go](widget/utils.go) for read-only `View` output; [widget/view_escaping_test.go](widget/view_escaping_test.go) locks this in for the lookup widgets.
- **LookupCode Labels are end-user data.** They arrive through a `LookupProvider` and may hold whatever a user typed. Every widget `View` and `Edit` must draw them with `InnerText` (via `drawValue`, `selectedCode`, `selectedLabels`). The one sanctioned raw write is `WYSIWYG.View`, whose stored value IS markup by design — sanitize before storage, not there.
- **The form DEFINITION is trusted and deliberately unescaped.** Layout titles and widget descriptions go through `InnerHTML`, and options like `style`, `script`, and `show-if` are written straight into tags. Form definitions must come from application code or an administrator, never from an end user. Do not "harden" these paths by escaping them — the `html` and `heading` widgets exist precisely to emit authored markup.
- **A data value written into a hyperscript string needs hyperscript quoting, not just HTML escaping.** `Script()` escapes the attribute, but the browser decodes it before hyperscript reads it, so a stored `'` still ends a `'…'` literal and runs whatever follows as hyperscript. `select-group` passes its stored child value and its options JSON through `hyperscriptQuote` in [widget/select-group.go](widget/select-group.go), and [widget/select-group_test.go](widget/select-group_test.go) decodes the literal the way hyperscript does to pin it.
- **The `html-remote` widget executes its `url` option as a `text/template` against the form's value.** Another reason definitions are a trust boundary: a hostile definition is template injection by construction.

## SetURLValues and the write path

- **`Schema.Set` failures are logged at debug level and skipped, never returned.** One rejected field must not abandon the rest of the form, so `SetURLValues` in [form.go](form.go) deliberately drops invalid values (rosetta's `Set` validates, clamps, and truncates before writing). Do not refactor this into an early return; equally, do not expect `SetURLValues` to report bad input to the caller.
- **Only visible, writable elements are written — that is the mass-assignment guard.** `SetURLValues` walks the element tree and skips an element, AND everything inside it, when it is `ReadOnly`, when its `show-if-option` is not TRUE or its `hide-if-option` is TRUE in `Form.Options`, or when its `show-if` expression evaluates false against the object. So a `show-if` on a container gates its children's writes, as the layout widgets' `showIf` wrapper hides them. Until 2026-11-05 the walk was `Element.AllElements()`, which flattens to path-bearing elements, so a posted field under a hidden container, or behind a false `show-if-option`, was written anyway; Emissary's Bluesky toggle was the live case. `AllElements()` still exists for Emissary's `edit-table` step and still does not know about either.
- **A caller must build the POST form with the same `Form.Options` as the GET.** A missing option reads as FALSE, so a form saved without its options refuses every `show-if-option` field and writes every `hide-if-option` field. The save path is also stricter than rendering in two places: `layout-tabs` draws its children without checking either option, and the root element is drawn without checking its own. Neither shape appears in any template today.
- **The two-pass `show-if` loop is important.** Elements that no `show-if` governs, on themselves or on a container above them, are written first, then the rest, so a dependent field is evaluated against its parent's freshly-written value. Collapsing this into one pass silently breaks dependent fields. Within the second pass the order is document order, so a `show-if` that names another conditional field placed below it sees that field's stored value, not its posted one.
- **Array-typed paths must be wrapped before `Schema.Set` — `schemaSafeValue` does it.** `url.Values` holds plain `[]string`, which rosetta cannot write through its `ArrayGetterSetter` interface; the helper wraps Array paths in `*sliceof.String` (an empty one when nothing was posted, so un-checking every option clears the array). New multi-value widgets get this for free only if they go through `Schema.Set`; a custom `URLValueSetter` must handle it itself.
- **The `list` widget's cleanup has a twin in the browser, and the two must agree.** `cleanList` in [widget/list.go](widget/list.go) trims, drops blanks, and drops repeats by `strings.ToLower`, and Emissary's `ListWidget` behavior marks a repeat by `toLowerCase()` and counts kept values against the Array's `minLength`. A change to one rule without the other marks rows the server keeps, or lets a Save through that the schema then refuses with only a debug log. The two folds already differ for a few characters, such as the Turkish dotted İ.
- **A value written into HTML goes through `form.FormatValue`, never `convert.String`.** rosetta's `convert.String` rounds floats to two decimals, so a select rendered `0.125` as `"0.12"` and posted a value its schema refused, and every save of a `place` moved its coordinates (`40.712776` became `"40.71"`). `FormatValue` keeps two decimals when they are exact and every digit when they are not. `Element.GetString`, `GetSliceOfString`, and lookup codes already use it; a new widget that writes a value attribute must too. `formatValue_test.go` and the `*Fractional*` tests pin it.
- **A `schema.Number` input defaults to `step="0.01"`, so a browser will not submit a stored value with more decimals.** Give the element a `step` option that matches the data's precision; `step` itself renders through `FormatValue`, so `0.001` survives.
- **The `::NEWVALUE::` sentinel (`form.NewItemIdentifier`) must match the hyperscript in `widget/select.go`.** `Element.replaceNewLookup` strips that prefix and calls `WritableLookupGroup.Add` on save; changing the literal in one place silently breaks "add another" options. The "+ Add Another..." option is itself valued `::NEWVALUE::`, so cancelling or blanking the prompt posts the bare sentinel. A blank or whitespace-only name fails the whole save with a `derp.Validation` error before `Add` is called, whatever the provider; Emissary's `Add` implementations created a nameless Circle, Group, or Folder from it until 2026-11-05.
- **A multi-file field has no wire format here, because `html-remote` loads it and the host posts it.** Emissary's `edit-attachments` draws the whole zone behind an `html-remote`, with its file input and the hidden `{field}.order` inputs its tiles post, so the field names are the host's and live with its step (Emissary's `build` package). There was an `upload-multiple` widget here for that from 2026-11-03 to 2026-11-04, with `form.UploadOrderSuffix` as the order field's constant and, for a few hours, an `ActionURLProvider` interface that let the host name the URL; all three are gone, because `html-remote` already loads a URL, and the template writes it (Ben, 2026-11-04). `UploadNewPrefix` went on 2026-11-03 with the Save-time upload it served. `html-remote` loads on `load` rather than `intersect once` since the same day, and shows its label and description, which no template in Emissary, qwertylicious, Atlas, or Bandwagon depended on.

## Structure and callers

- **This package never emits the `<form>` tag.** Callers own the action URL, method, and enctype; `Form.Encoding()` (fed by each widget's `Encoding` method, promoted through layout children) is the only contribution — a caller that ignores it breaks `upload` widgets. Emissary's `WrapForm` is the canonical consumer, and it uses relative action URLs on purpose (absolute config-derived URLs drop the browser's port behind proxies).
- **`Element.Options` is a `mapof.Template`: every option can be a template, so pass the object being drawn to every getter.** Parsing an Element (`Parse`/`UnmarshalMap`, or JSON through `mapof.Template.UnmarshalJSON`) stores every string option that compiles as a template (a `{{` followed by `}}`) as a rosetta `loose.Template`. A malformed template does not fail the parse: it stays a plain string and renders literally. Every getter is `GetXxx(key, value)` and renders against the object, so templates name its fields (`{{.ID}}`); pass `nil` only where no object exists (loading lookups, `validateSchema`, the table header), which returns the source. A failed render reads as `""`; `text`'s `validator`, `upload`'s `delete`, and `html-remote`'s `url` use `Evaluate` instead, so that a broken URL fails the render. Rendering never writes to the Element: a parsed form is shared by every request, and writing rendered values back into it fixed every form to the first object rendered after a restart (Emissary BUG-204). A `mapof.Template` literal written in Go is never parsed, so its template strings compile on first use through rosetta's `loose.CachedTemplate`, never into the map.
- **A templated bool must render `true` or `false` in both cases, and a number must render only digits.** `{{if .X}}true{{end}}` renders `""` when `.X` is false, which `GetBoolOK` reports as absent, so the widget falls back to its default. Write `{{if .X}}true{{else}}false{{end}}`. `convert.Bool` rejects `1` and `yes`. The bool and number getters trim surrounding whitespace, but not whitespace inside the text.
- **Any option holding `{{` and a later `}}` is executed.** A literal brace pair in a placeholder, description, or hyperscript option would render against the object. None do today (audited 2026-09-27: only `validator` and `delete` hold templates).
- **Two different things are called "options".** `Element.Options` is a per-widget `mapof.Any` from the JSON definition; `Form.Options` is a `[]string` of `"name:value"` pairs read by `OptionString`/`OptionBool`, by the `show-if-option`/`hide-if-option` switches in the `layout-*` and `container` widgets, and by `SetURLValues`. An `Element.Options` entry names a `Form.Options` key; the two are otherwise unrelated.
- **`Form.Validate()` catches definition mistakes; `UnmarshalJSON` calls it automatically.** It checks every `Path` and every field named in a `show-if` expression against the schema. Forms built in Go code or via `Parse` are NOT auto-validated — call it yourself when loading a definition from storage.
- **`benpate/table` renders its cells through this package.** Table columns are `form.Element`s drawn per-row, so registry, escaping, and schema rules above all apply there too; see that repo's AGENTS.md.

## An absent value and a stored FALSE are not the same thing, and a toggle collapses them

`widget/toggle.go` resolves an unset path through `toggleValue`, which falls back to the schema's `DefaultValue()` rather than rendering OFF. Both `View` and `Edit` go through it. This matters because a toggle always posts either `"true"` or `"false"`: without the fallback, a form whose object has never been saved displays OFF for a setting that defaults ON, and then posts that phantom FALSE on the first save — silently turning off something nobody touched. Any new widget with a fixed set of posted values owes its absent case the same treatment.
